## User Story
As a General Ledger accountant,
I want to add, view, and manage individual debit and credit line items on a journal entry,
So that I can record the full double-entry detail of a financial transaction against specific GL accounts.

## Functional Requirements
1. The journal entry form must display a line-items grid below the header section.
2. Each line item must capture the following fields: Line Number (auto-assigned sequential integer), Account (chartfield combination code), Account Description (auto-populated from the account code), Currency ID, Debit amount, Credit amount, Description (per-line free text), Reference Number (per-line free text).
3. The Account (chartfield) field must accept a structured 5-segment code in the format `S1-S2-S3-S4-S5` where each segment has a distinct business meaning. Segment 1 represents the Country code. The business meanings of Segments 2–5 are pending OQ-006 resolution but are confirmed to carry distinct identifiable information (e.g. entity, department, GL account, cost centre).
3. Account Description must be automatically populated when a valid account code is entered — the user must not need to type it manually.
4. A line item must have either a Debit amount or a Credit amount populated — not both on the same line. The non-entered amount must display as zero or blank.
5. The user must be able to add new line items to the grid.
6. The user must be able to delete existing line items from the grid.
7. Each line must display its sequential line number (1, 2, 3…).
8. Currency ID must be selectable or defaulted per line; multi-currency behaviour is pending clarification on OQ-007.
9. The grid must support at least 3 visible line items and scroll to accommodate more.

## Acceptance Criteria
1. Given a journal entry is open, when the line-items grid is rendered, then each row shows: line number, account code, account description, currency, debit amount, credit amount, line description, and reference number.
2. Given the user enters a valid account code on a line, when the cursor leaves the account field, then the Account Description field is automatically populated with the account name.
3. Given the user enters a debit amount on a line, when the value is entered, then the credit amount field on the same line remains zero or empty (cannot enter both).
4. Given the user enters a credit amount on a line, when the value is entered, then the debit amount field on the same line remains zero or empty (cannot enter both).
5. Given the user clicks the "add line" control, when a new line is added, then it appears at the bottom of the grid with the next sequential line number and all fields empty.
6. Given a line item exists, when the user deletes it, then it is removed from the grid; line number renumbering behaviour is pending OQ-008 resolution.
7. Given more than the visible row limit of line items, when the grid is rendered, then a scrollbar is provided to access all lines.

## Non-Functional Requirements

| Security      | Only entries in "Unposted" status may have line items added or deleted.        |
| Accessibility | Grid rows must be keyboard-navigable; field labels must be associated with inputs. |
| Usability     | The grid must display a minimum of 5 lines without scrolling on a standard 1280×800 display. |

## UI Components Affected
- Line-items data grid
- Account code input with auto-populate lookup
- Debit / Credit numeric inputs (mutually exclusive per row)
- Per-line description and reference text inputs
- Add row / Delete row controls
- Grid scroll container

## BFF Endpoints Needed
- GET /journal-entries/{journalId}/lines — return all line items for a journal entry
- POST /journal-entries/{journalId}/lines — add a new line item
- PUT /journal-entries/{journalId}/lines/{lineId} — update an existing line item
- DELETE /journal-entries/{journalId}/lines/{lineId} — delete a line item
- GET /accounts/{accountCode} — look up account description and validate account code
