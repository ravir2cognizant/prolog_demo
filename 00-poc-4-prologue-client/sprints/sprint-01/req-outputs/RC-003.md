## User Story
As a General Ledger accountant,
I want to create a new journal entry or edit an existing unposted entry by entering header information,
So that I can record or correct the metadata for a financial transaction.

## Functional Requirements
1. The system must allow a user to create a new journal entry by providing: Company ID, Journal Entry Type, Transaction Date, and Description at minimum.
2. Company ID must be selectable from a dropdown of available companies, displaying code and name.
3. Journal Entry Type must be selectable from a dropdown of available types (e.g. Finance Journal).
4. Transaction Date must be enterable via a date input control.
5. Description must be editable as a free-text field; maximum length is not specified in the source (see OQ-005).
6. Auto Reversal Date must be an optional date field that can be left empty.
7. Allocation Method ID must be an optional field that can be left empty.
8. The system must auto-populate Journal Number upon creation (system-generated sequential identifier).
9. The system must auto-populate Edit Date/Time with the current timestamp when the entry is saved.
10. The system must auto-populate Edit User ID with the authenticated user's identifier when the entry is saved.
11. Editing must be restricted to entries in "Unposted" status — posted entries must not be editable.

## Acceptance Criteria
1. Given the user initiates a new journal entry, when the form is displayed, then Company ID, Journal Entry Type, Transaction Date, and Description fields are available for input.
2. Given the user selects a Company ID from the dropdown, when the selection is made, then the field displays "code - name" format.
3. Given the user selects a Journal Entry Type, when the form is submitted, then the selected type is persisted on the entry.
4. Given the user saves a journal entry, when the save completes successfully, then Edit Date/Time is updated to the current server timestamp and Edit User ID reflects the authenticated user.
5. Given the entry is in "Unposted" status, when the user accesses the form, then all editable fields are enabled for input.
6. Given the entry is in "Posted" status, when the user accesses the form, then editable fields are read-only (cannot be modified).
7. Given Auto Reversal Date is left empty, when the entry is saved, then it is stored without an auto reversal date — no validation error is raised.

## UI Components Affected
- Journal entry header form (edit mode)
- Company ID dropdown
- Journal Entry Type dropdown
- Date picker (Transaction Date, Auto Reversal Date)
- Free-text input (Description)
- Save / Cancel action buttons in toolbar

## BFF Endpoints Needed
- POST /journal-entries — create a new journal entry header
- PUT /journal-entries/{journalId} — update an existing unposted journal entry header
- GET /reference/companies — return list of available companies for dropdown
- GET /reference/journal-entry-types — return list of journal entry types for dropdown
