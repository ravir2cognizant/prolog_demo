## Component Tree

```
JournalEntryHeader                  (shared with CI-002 — audit fields are part of header)
├── StatusBadge                     (RC-006 FR-3: lifecycle status display — also in CI-002)
├── AuditFieldGroup                 (groups all four audit trail read-only fields)
│   ├── ReadOnlyField (Edit Date/Time)
│   ├── ReadOnlyField (Edit User ID)
│   ├── ReadOnlyField (Posted Date/Time)
│   └── ReadOnlyField (Poster User ID)
└── PostEntryButton                 (triggers POST /journal-entries/{journalId}/post)
    (only visible when status === "Unposted" and entry is balanced)
```

RC-006 components are integrated into `JournalEntryHeader` (CI-002). Components `StatusBadge` and `ReadOnlyField` are shared and documented here for audit-trail-specific behaviour only.

## Components

### AuditFieldGroup
| Prop | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| editDateTime | `string` | Yes | — | ISO 8601 datetime; formatted as locale datetime for display |
| editUserId | `string` | Yes | — | User identifier who last saved |
| postedDateTime | `string \| null` | Yes | — | Null when not yet posted |
| posterUserId | `string \| null` | Yes | — | Null when not yet posted |

### PostEntryButton
| Prop | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| journalId | `number` | Yes | — | Journal entry to post |
| isBalanced | `boolean` | Yes | — | Post action only enabled when entry is balanced |
| isPosting | `boolean` | No | `false` | Shows loading state during POST request |
| onPostSuccess | `(result: PostResult) => void` | Yes | — | Callback on successful post |
| onPostError | `(error: string) => void` | Yes | — | Callback on post failure |

### PostResult (from POST /journal-entries/{journalId}/post response)
| Field | Type | Description |
|-------|------|-------------|
| status | `"Posted"` | Updated status |
| postedDateTime | `string` | Server timestamp of posting |
| posterUserId | `string` | User who posted |

## States

### StatusBadge States (RC-006 specific — extends CI-002)
| Status | Badge Style | Description |
|--------|------------|-------------|
| "Unposted" | Amber background, amber text (`.badge-unposted`) | Entry not yet posted |
| "Posted" | Green background, green text (`.badge-posted`) | Entry posted to ledger |

### AuditFieldGroup States
| State | Visual |
|-------|--------|
| Unposted | `editDateTime` and `editUserId` populated; `postedDateTime` and `posterUserId` show em-dash |
| Posted | All four fields populated |
| All fields | Render as `ReadOnlyField` with `grey100` background — never editable |

### PostEntryButton States
| State | Visual | Condition |
|-------|--------|-----------|
| Default | `btn-primary` green; "Post Entry" label | `isBalanced === true`, `status === "Unposted"` |
| Disabled — unbalanced | 50% opacity; `cursor: not-allowed`; tooltip "Entry must be balanced before posting" | `isBalanced === false` |
| Posting | Spinner + "Posting…" label; button disabled | `isPosting === true` |
| Hidden | Not rendered | `status === "Posted"` |

## Validation Rules
| Rule | Detail |
|------|--------|
| All audit fields read-only | No input component may be rendered for editDateTime, editUserId, postedDateTime, posterUserId (RC-006 FR-6, FR-9) |
| Post requires balance | `PostEntryButton` disabled when `isBalanced === false`; server also enforces this (400 response) |
| Posted state is terminal | Once status is "Posted", PostEntryButton is removed; no further edits possible |
| Null display | `postedDateTime === null` and `posterUserId === null` must display as em-dash, not "null" |

## Accessibility
| Requirement | Implementation |
|-------------|---------------|
| Status announcement | `StatusBadge` uses `role="status"` and `aria-live="polite"` so screen readers announce status changes after post |
| Audit field labels | Each `ReadOnlyField` in AuditFieldGroup uses `<dt>` / `<dd>` in a `<dl>` description list |
| Post button label | `aria-label="Post this journal entry"` for clarity beyond visual label |
| Post confirmation | On successful post, focus moves to StatusBadge and screen reader announces new status via live region |
| Post disabled reason | `aria-describedby` links to a helper text element explaining why the button is disabled |
| Contrast | All audit field text and status badge colors meet WCAG AA 4.5:1 |
