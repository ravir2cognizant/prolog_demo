## Shared Endpoint — Read (no new GET endpoint)

RC-006 audit trail fields are included in the `GET /journal-entries/{journalId}` response defined in **ED-002**. No additional GET endpoint is required for RC-006.

Audit fields returned in ED-002 response that satisfy RC-006:

| ED-002 Response Field | RC-006 Requirement | Notes |
|----------------------|-------------------|-------|
| `status` | FR-1, FR-2, FR-3 | Lifecycle status ("Unposted" / "Posted") |
| `editDateTime` | FR-4, FR-6 | Timestamp of last save; system-populated, read-only |
| `editUserId` | FR-5, FR-6 | User who last saved; system-populated, read-only |
| `postedDateTime` | FR-7 | Null for Unposted; timestamp when Posted |
| `posterUserId` | FR-8 | Null for Unposted; pending OQ-002 re: pre-population |

All audit fields are **read-only** — no API endpoint accepts user-provided values for these fields (enforced at the BFF layer).

## New Endpoint — Post Journal Entry

RC-006 identifies that a posting action triggers status transition from "Unposted" to "Posted". While the exact mechanism is pending OQ-009 resolution, the following endpoint is designed as a placeholder.

### Post Journal Entry
| Field          | Value                                                                            |
|----------------|----------------------------------------------------------------------------------|
| HTTP Method    | POST                                                                             |
| URL Path       | /journal-entries/{journalId}/post                                                |
| Authentication | Required (Bearer JWT)                                                            |
| Description    | Transitions a journal entry from "Unposted" to "Posted" status. Sets `postedDateTime` to the current server timestamp and `posterUserId` to the authenticated user. The server validates that the entry is balanced before allowing posting. **Pending OQ-009**: additional lifecycle states (Rejected, In Review, Reversed, Void) may require additional transition endpoints. |

#### Request Model
| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| journalId | integer (path) | Yes | Must be a positive integer | Journal entry to post |

#### Response Model — 200 OK
| Field | Type | Description |
|-------|------|-------------|
| journalId | integer | Journal entry identifier |
| status | string | Updated status: "Posted" |
| postedDateTime | string (ISO 8601 datetime) | Server timestamp of posting |
| posterUserId | string | Authenticated user who performed the post action |

#### Error Responses
| Status Code | Condition | Response Body |
|-------------|-----------|---------------|
| 400 | Entry is not balanced (totalDebits ≠ totalCredits) or is already posted | `{ "error": "[message]" }` |
| 401 | Unauthenticated | `{ "error": "Unauthorised" }` |
| 403 | User does not have posting authority | `{ "error": "Forbidden" }` |
| 404 | Journal entry not found | `{ "error": "Journal entry not found" }` |
| 500 | Internal server error | `{ "error": "Internal server error" }` |

## Design Notes
- Audit fields (`editDateTime`, `editUserId`, `postedDateTime`, `posterUserId`) must NOT be accepted in any request body — they are server-populated only.
- OQ-002 (Poster User ID pre-population): Conservative design — `posterUserId` is null until posting occurs.
- OQ-009 (additional lifecycle statuses): The POST /post endpoint handles the "Unposted → Posted" transition. Additional transitions (e.g. Reject, Reverse) will require new endpoints and are not in scope for Sprint-01.
- The `POST /journal-entries/{journalId}/post` endpoint is a new endpoint not listed in RC-006's "BFF Endpoints Needed" section, but is required to implement FR-1/FR-2 (status management) and AC-2 (entry posts correctly). It is added here based on A-02 semantic analysis.
