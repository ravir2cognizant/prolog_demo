## Endpoint Definitions

### Create Journal Entry
| Field          | Value                                                                             |
|----------------|-----------------------------------------------------------------------------------|
| HTTP Method    | POST                                                                              |
| URL Path       | /journal-entries                                                                  |
| Authentication | Required (Bearer JWT)                                                             |
| Description    | Creates a new journal entry header. The server auto-assigns journal number, sets initial status to "Unposted", and populates edit audit fields from the authenticated session. |

#### Request Model
| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| companyId | string | Yes | Must match an accessible company code for the authenticated user | Company code for the journal entry |
| journalEntryType | string | Yes | Must match a valid journal entry type code | Journal entry type (e.g. "Finance Journal") |
| transactionDate | string (ISO 8601 date) | Yes | Valid date; not null | Date of the financial transaction |
| description | string | Yes | Non-empty string; max length pending OQ-005 resolution — enforce 500 chars as default | Free-text description of the journal entry |
| autoReversalDate | string (ISO 8601 date) \| null | No | Valid date if provided | Optional auto-reversal date |
| allocationMethodId | string \| null | No | Valid allocation method ID if provided | Optional allocation method identifier |

#### Response Model — 201 Created
| Field | Type | Description |
|-------|------|-------------|
| journalId | integer | System-assigned unique identifier for the new entry |
| journalNumber | integer | System-assigned sequential journal number |
| status | string | Initial status: "Unposted" |
| editDateTime | string (ISO 8601 datetime) | Server timestamp of creation |
| editUserId | string | Authenticated user identifier |

#### Error Responses
| Status Code | Condition | Response Body |
|-------------|-----------|---------------|
| 400 | Missing required field or validation failure | `{ "error": "[message]", "field": "[fieldName]" }` |
| 401 | Unauthenticated | `{ "error": "Unauthorised" }` |
| 403 | User does not have create access to the specified company | `{ "error": "Forbidden" }` |
| 500 | Internal server error | `{ "error": "Internal server error" }` |

### Update Journal Entry Header
| Field          | Value                                                                           |
|----------------|---------------------------------------------------------------------------------|
| HTTP Method    | PUT                                                                             |
| URL Path       | /journal-entries/{journalId}                                                    |
| Authentication | Required (Bearer JWT)                                                           |
| Description    | Updates the header of an existing journal entry. Only permitted for entries in "Unposted" status. Server updates edit audit fields automatically. |

#### Request Model
| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| journalId | integer (path) | Yes | Must be a positive integer | Journal entry to update |
| journalEntryType | string | No | Must match a valid journal entry type code if provided | Journal entry type |
| transactionDate | string (ISO 8601 date) | No | Valid date if provided | Transaction date |
| description | string | No | Non-empty string if provided; max length pending OQ-005 | Free-text description |
| autoReversalDate | string (ISO 8601 date) \| null | No | Valid date if provided; null to clear | Auto-reversal date |
| allocationMethodId | string \| null | No | Valid ID if provided; null to clear | Allocation method |

#### Response Model — 200 OK
| Field | Type | Description |
|-------|------|-------------|
| journalId | integer | Journal entry identifier |
| editDateTime | string (ISO 8601 datetime) | Updated server timestamp |
| editUserId | string | Authenticated user identifier |

#### Error Responses
| Status Code | Condition | Response Body |
|-------------|-----------|---------------|
| 400 | Validation failure or invalid field value | `{ "error": "[message]", "field": "[fieldName]" }` |
| 401 | Unauthenticated | `{ "error": "Unauthorised" }` |
| 403 | User lacks edit access or entry is in "Posted" status | `{ "error": "Forbidden" }` |
| 404 | Journal entry not found | `{ "error": "Journal entry not found" }` |
| 500 | Internal server error | `{ "error": "Internal server error" }` |

## Design Notes
- OQ-004 (which fields lock after initial creation) is open. The PUT endpoint accepts all mutable fields; the server enforces lock-down rules. This design is forward-compatible with OQ-004 resolution.
- OQ-005 (mandatory fields and max lengths) is open. The description max length defaults to 500 chars pending resolution.
- `companyId` is NOT in the PUT body — company changes post-creation are blocked server-side (pending OQ-004b in RC-008). If OQ-004b resolves to "company is mutable," add it to PUT body in a future revision.
- GET /reference/companies is also documented in ED-008 (RC-008 Company Selection). Both ED files reference the same endpoint.
