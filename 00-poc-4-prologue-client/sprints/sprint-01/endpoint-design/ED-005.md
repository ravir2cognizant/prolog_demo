## No New BFF Endpoints

RC-005 explicitly states: **"BFF Endpoints Needed: None — balance totals are calculated client-side from line item data already loaded."**

The balance display (Total row, Difference row) is a **client-side calculation** performed on the line items data returned by:
- `GET /journal-entries/{journalId}` (ED-002) — initial page load: `lines` array + `totals` object included in the response
- `GET /journal-entries/{journalId}/lines` (ED-004) — targeted refresh after mutations

## Server-side Balance Fields

Although the running totals are recalculated client-side for real-time UX, the server provides the following computed fields in the `GET /journal-entries/{journalId}` response (defined in ED-002):

| Field in Response | Type | Purpose |
|-------------------|------|---------|
| `totals.totalDebits` | number | Sum of all line item debit amounts |
| `totals.totalCredits` | number | Sum of all line item credit amounts |
| `totals.difference` | number | totalDebits − totalCredits |
| `balanced` | boolean | System-calculated flag: true when totalDebits = totalCredits (HB-001 resolved — this is NOT user-settable) |

## Recalculation Behaviour

The `balanced` flag and `totals` values are:
- Returned by the server on every `GET /journal-entries/{journalId}` call
- Returned in the response of `POST /journal-entries/{journalId}/lines`, `PUT /journal-entries/{journalId}/lines/{lineId}`, and `DELETE /journal-entries/{journalId}/lines/{lineId}` (mutations include updated totals in their response payloads — see ED-004)
- OQ-001b (recalculation trigger for the `balanced` flag: on save vs on line edit) is open. The conservative design is: the server recalculates on every write operation and the client recalculates locally for immediate display.

## Client-Side Calculation Contract

The frontend must implement real-time running totals:
- On every line item add, edit, or delete: sum `debitAmount` and `creditAmount` across all lines in local state
- Display `totalDebits`, `totalCredits`, and `difference` immediately without waiting for a server response
- Sync with server `totals` values on the next GET or on save confirmation
