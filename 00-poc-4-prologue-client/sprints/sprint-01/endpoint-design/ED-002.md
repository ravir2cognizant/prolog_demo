## Endpoint Definitions

### Get Journal Entry (Header + Line Items)
| Field          | Value                                                                          |
|----------------|--------------------------------------------------------------------------------|
| HTTP Method    | GET                                                                            |
| URL Path       | /journal-entries/{journalId}                                                   |
| Authentication | Required (Bearer JWT)                                                          |
| Description    | Returns the full journal entry record: all 16 header fields, all line items, and audit trail fields. This is the primary read endpoint consumed by RC-002, RC-006, and the balance display in RC-005. |

#### Request Model
| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| journalId | integer (path) | Yes | Must be a positive integer | Unique journal entry identifier |

#### Response Model — 200 OK

**Journal Entry object:**
| Field | Type | Description |
|-------|------|-------------|
| journalId | integer | System-assigned unique identifier |
| companyId | string | Company code (e.g. "0004") |
| companyName | string | Company name (e.g. "0004_company") |
| journalEntryType | string | Type code (e.g. "Finance Journal") |
| journalNumber | integer | Sequential journal number |
| status | string | Lifecycle status: "Unposted" or "Posted" |
| transactionDate | string (ISO 8601 date) | Date of the financial transaction |
| editDateTime | string (ISO 8601 datetime) | Timestamp of last save |
| editUserId | string | User identifier who last saved the entry |
| autoReversalDate | string (ISO 8601 date) \| null | Auto reversal date; null if not set |
| description | string | Free-text journal entry description |
| postingSession | string \| null | Posting session identifier; null if not set |
| sourceDocument | string \| null | Source document reference; null if not set |
| glImport | string \| null | GL import reference; null if not set |
| allocationMethodId | string \| null | Allocation method identifier; null if not set |
| balanced | boolean | System-calculated flag: true when Total Debits = Total Credits (see RC-005 / HB-001) |
| postedDateTime | string (ISO 8601 datetime) \| null | Timestamp of posting; null if not posted |
| posterUserId | string \| null | User who posted the entry; null if not posted |
| lines | array\<LineItem\> | All line items for this journal entry (see ED-004 for LineItem schema) |
| totals | JournalTotals | Computed totals for balance display |

**JournalTotals object:**
| Field | Type | Description |
|-------|------|-------------|
| totalDebits | number | Sum of all debit amounts across line items |
| totalCredits | number | Sum of all credit amounts across line items |
| difference | number | totalDebits minus totalCredits |

#### Error Responses
| Status Code | Condition | Response Body |
|-------------|-----------|---------------|
| 400 | journalId is not a valid positive integer | `{ "error": "Invalid journal ID" }` |
| 401 | Unauthenticated | `{ "error": "Unauthorised" }` |
| 403 | User does not have view access to this journal entry's company | `{ "error": "Forbidden" }` |
| 404 | Journal entry not found | `{ "error": "Journal entry not found" }` |
| 500 | Internal server error | `{ "error": "Internal server error" }` |

## Design Notes
- The `balanced` flag is system-calculated and returned by the server on every GET response. It is NOT user-settable. (HB-001 resolved.)
- `totals` is included in the response to support the balance display (RC-005) without requiring a separate client-side sum — the client MAY recalculate for real-time UX but the server value is authoritative.
- `posterUserId` and `postedDateTime` must be null when status is "Unposted". OQ-002 (pre-population from session) is open — null is the safe default.
- This endpoint is shared by RC-002 (header view), RC-006 (audit trail display), and RC-005 (balance totals). See also ED-006.
- The `lines` array is included inline to avoid a separate round trip on initial page load (see ED-004 for dedicated line-item endpoints).
