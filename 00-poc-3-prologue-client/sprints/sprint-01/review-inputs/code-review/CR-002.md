# CR-002: Data fetching via useEffect instead of React Router loader functions

## Issue
All three real feature pages load API data via `useEffect` + `useState` rather than React Router 7 `loader` functions. The review checklist item states "React Router loaders for data fetching."

Pattern currently used in each page:
```typescript
useEffect(() => {
  apiClient.GET('/companies').then(({ data }) => {
    setCompanies(data?.items ?? []);
  });
}, []);
```

## Assessment
This is an **architectural gap, not a bug**. For this POC sprint, the pages function correctly. React Router loader functions would provide:
- Data available before component renders (no loading flicker)
- Automatic error boundaries via `errorElement`
- Cleaner separation of data and display concerns

For a first-sprint POC with mock data (MSW, offline mode), `useEffect` is pragmatically acceptable. No user-visible defect arises from this pattern given the fast MSW responses.

## Recommendation
In a future sprint, migrate the three real pages to Route `loader` functions in `routes.tsx` and consume data via `useLoaderData()`. This is a refactor task, not a blocker.
