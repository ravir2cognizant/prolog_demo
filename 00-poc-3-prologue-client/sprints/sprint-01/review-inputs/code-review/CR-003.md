# CR-003: Three hard-coded English strings bypass i18next

## Issue
Three strings are hard-coded in English rather than routed through `t()`:

| File | Line | Hard-coded string |
|------|------|------------------|
| `src/routes.tsx` | 22 | `"Loading..."` (Loading fallback div) |
| `src/components/DataTable.tsx` | 24 | `"No records found."` (default prop value) |
| `src/components/DataTable.tsx` | 47 | `"Loading..."` (table body loading cell) |

All other visible strings in the codebase use `t()` with keys from `src/locales/en.json`.

## Assessment
Minor localisation gap. The keys `common.loading` and `common.noResults` already exist in `en.json`. The fix is mechanical.

## Recommended fix

**routes.tsx:22**
```tsx
// Replace:
<div className="...">Loading...</div>
// With: (note: useTranslation not available in this non-component function;
// either hardcode acceptable or extract to a LoadingFallback component)
<div className="...">Loading...</div>  {/* acceptable as infrastructure text */}
```
For the Loading fallback in routes.tsx, a hardcoded string is defensible (it's infrastructure plumbing, not UI copy). The DataTable instances are higher-priority.
