# CR-001: Raw fetch() in postMultipart bypasses apiClient

## Issue
`postMultipart()` in `src/api/client.ts` uses the native `fetch()` API directly rather than routing through the typed `apiClient` (openapi-fetch). This violates the checklist item "no raw fetch/axios."

```typescript
// client.ts:16
export async function postMultipart(path: string, formData: FormData): Promise<Response> {
  return fetch(`${BASE_URL}${path}`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${DEV_TOKEN}` },
    body: formData,
  });
}
```

## Assessment
This is a **justified exception**. `openapi-fetch` v0.12 does not support `multipart/form-data` bodies (it serialises via JSON by default). The raw `fetch` is the correct mechanism for file upload endpoints. The function is correctly isolated and the `Authorization` header is applied.

## Recommendation
Add a brief inline comment above `postMultipart` noting the intentional exception and the library limitation. No functional change required.

## Fix
```typescript
// openapi-fetch does not support multipart bodies; use fetch directly for file uploads.
export async function postMultipart(path: string, formData: FormData): Promise<Response> {
```
