# CR-005: Reference-data endpoints are unauthenticated

## Issue
The following endpoints are registered in `shell.routes.ts` and mounted in `routes/index.ts` **before** the `authn` middleware, meaning they receive no bearer-token authentication:

- `GET /companies`
- `GET /currencies`
- `GET /journal-entry-types`
- `GET /source-documents`
- `GET /allocation-methods`
- `GET /routing-rules`

```typescript
// routes/index.ts
router.use('/', shellRoutes);   // mounts public + reference-data routes — line 17
router.use(authn);              // auth gate applied AFTER — line 20
router.use('/journal-entries', jeRouter);
// ...
```

The inline comment says "Protected reference-data routes" which contradicts the implementation.

## Assessment
This is a **design choice** for the POC, not a defect. Reference data (company list, currency codes, entry type codes) is commonly needed by login/selector UIs before authentication and contains no sensitive personal data. `AUTH_DEV_BYPASS=1` further underscores the dev-only context.

The inaccurate comment is a minor documentation issue.

## Recommendation
1. Remove or update the misleading comment.
2. For production: decide per-endpoint whether bearer auth is required. `/companies` may warrant auth if company names are considered confidential.
