# CR-004: Missing reset() call on company change in AccountMaintenancePage

## Issue
When the user changes the company selector in `AccountMaintenancePage`, the handler calls `setSelectedId(null); setIsNew(false)` but does **not** call `reset()` on the react-hook-form instance. If an account was loaded in the form before the company change, the form fields (`code`, `description`, `type`, `active`) retain stale values from the previously selected account until a new account is explicitly selected.

```typescript
// Current implementation:
onChange={(e) => { setCompanyId(e.target.value); setSelectedId(null); setIsNew(false); }}

// Missing:
// reset({ companyId: e.target.value, code: '', description: '', type: 'asset', active: true });
```

## Assessment
**Low** risk in practice. Because `setSelectedId(null)` causes the form panel to render `"No records found."` (hidden state), the stale RHF values are never visible to the user. However, if a user navigates back to the previously edited account, the form registers with stale dirty-field state. More importantly, it can cause unexpected `isDirty` === `true` warnings.

## Recommended fix
```typescript
onChange={(e) => {
  const next = e.target.value;
  setCompanyId(next);
  setSelectedId(null);
  setIsNew(false);
  reset({ companyId: next, code: '', description: '', type: 'asset', active: true });
}}
```
