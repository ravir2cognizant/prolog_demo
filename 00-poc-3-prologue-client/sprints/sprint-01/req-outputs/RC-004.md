## User Story
As a GL supervisor,
I want to post a balanced journal entry to the general ledger and have the system record the posting date, time, and the posting user's ID,
So that I can control which entries are included in GL balances and maintain a clear posting audit trail.

## Functional Requirements
1. A journal entry must have a Status field that reflects its lifecycle state. Initial state is "Unposted".
2. The system must provide a Post action that changes the entry's Status from "Unposted" to "Posted".
3. When a journal entry is posted, the system must automatically record the Posted Date/Time (current timestamp) and Posted User ID (current user).
4. The system must set the Posted flag to "Yes" when posting is complete.
5. The system must prevent posting of an unbalanced journal entry (Difference ≠ $0.00) -- see RC-003.
6. The system must prevent editing of a posted entry's lines or Transaction Date without an explicit unpost or reversal action.
7. A posted entry must display its Status as "Posted", Posted Date/Time, and Posted User ID in read-only fields.
8. The system must support an Unpost action to revert a posted entry to "Unposted" status (subject to period control -- see RC-015).

## Acceptance Criteria
1. Given an unposted, balanced journal entry, when a user with post permission clicks Post, then the Status changes to "Posted", Posted = "Yes", Posted Date/Time is set to the current timestamp, and Posted User ID is set to the current user.
2. Given a user attempts to post an unbalanced journal entry, when the Post action is triggered, then the system rejects the action and displays "Cannot post: journal entry is not balanced."
3. Given a posted journal entry, when a user opens it, then all line fields and Transaction Date are read-only.
4. Given a user with unpost permission on a posted entry in an open period, when they invoke Unpost, then the Status reverts to "Unposted", the Posted Date/Time is cleared, and the entry is editable again.
5. Given a posted entry in a closed period, when a user attempts to Unpost, then the system rejects the action and displays "Cannot unpost: accounting period is closed."

## Non-Functional Requirements
| Category      | Requirement                                                                     |
|---------------|---------------------------------------------------------------------------------|
| Performance   | Post action must complete and return confirmation within 3 seconds.             |
| Security      | Post and Unpost actions require separate, explicitly granted permissions.        |
| Accessibility | Post/Unpost actions must be accessible via keyboard and labelled for screen readers.|
| Usability     | Status field must visually distinguish Posted vs Unposted state.                |
| Other         | Posting must be an atomic operation -- partial posts must not be possible.      |

## UI Components Affected
- Status field (read-only display)
- Posted field (Yes/No read-only)
- Posted Date/Time field (read-only)
- Posted User ID field (read-only)
- Post action button
- Unpost action button (conditionally visible)
- Inline validation message for blocked post

## BFF Endpoints Needed
- POST /journal-entries/{id}/post -- post a journal entry
- POST /journal-entries/{id}/unpost -- unpost a journal entry
- (Status is returned in GET /journal-entries/{id} response)

## Intra-sprint Dependencies
- Depends on: RC-003 -- balance validation must pass before posting is permitted.
- Depends on: RC-015 -- period control governs whether unposting is allowed.
