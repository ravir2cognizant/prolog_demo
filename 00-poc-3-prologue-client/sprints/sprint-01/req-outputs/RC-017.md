## User Story
As a GL administrator,
I want to create, edit, and look up GL accounts in the chart of accounts,
So that I can maintain the account master data and ensure accountants can find the correct account codes when creating journal entries or setting up allocation rules.

## Functional Requirements
1. The system must provide an Account Maintenance and Inquiry screen accessible from the General Ledger navigation.
2. Users must be able to create new GL accounts with at minimum: account code, account description, account type (asset, liability, equity, revenue, expense), and active/inactive status.
3. Users must be able to edit existing account records.
4. Users must be able to search and look up accounts by code or description.
5. The account inquiry view must show the account's current balance by period.
6. Inactive accounts must not appear in account picker dropdowns used in journal entry lines (RC-002) but must remain visible in the Account Maintenance screen.
7. Account codes visible in the source image follow a structured format (e.g. 1-394-7005-008-96, 1-741-7709-001-01) -- the account code structure must be enforced by the system.

## Acceptance Criteria
1. Given a user searches for an account by partial code or name, when the search is submitted, then a filtered list of matching accounts is displayed.
2. Given a user creates a new account with all required fields, when the account is saved, then it appears in the account picker in journal entry lines.
3. Given an account is marked inactive, when a user opens the account picker in a journal entry line, then the inactive account does not appear in the picker results.
4. Given a user opens the account inquiry view for an account, when the view loads, then the account's balance for each open accounting period is displayed.
5. Given a user enters an account code that does not match the required format, when they save, then the system rejects the entry with a message describing the required format.

## Non-Functional Requirements
| Category      | Requirement                                                              |
|---------------|--------------------------------------------------------------------------|
| Performance   | Account search must return results within 1 second for up to 50,000 accounts.|
| Security      | Account creation and editing requires GL administrator role.             |
| Accessibility | Account search field must be labelled and keyboard-accessible.           |
| Usability     | Account picker must support type-ahead search within journal entry lines.|
| Other         | Account code structure segment definition is pending confirmation; see Open Question OQ-044. |

## UI Components Affected
- Account Maintenance and Inquiry screen
- Account search/filter controls
- Account detail form (create/edit)
- Account inquiry balance view (by period)
- Account code input with format validation

## BFF Endpoints Needed
- GET /accounts?search={term}&companyId={id}&activeOnly={bool} -- search/list accounts
- GET /accounts/{id} -- get account detail
- POST /accounts -- create an account
- PUT /accounts/{id} -- update an account
- GET /accounts/{id}/balances?fiscalYearId={id} -- get account balances by period
