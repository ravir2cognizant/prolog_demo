## User Story
As a GL accountant,
I want to define allocation rules that distribute account balances to other accounts based on fixed amounts or percentage-based ratios,
So that I can automatically allocate shared costs, overheads, or revenues across departments or cost centres each period without manual journal entries.

## Functional Requirements
1. The system must provide an Account Balance Allocation module accessible from the General Ledger navigation.
2. Users must be able to define allocation rules specifying: source account(s), target account(s), and allocation basis (fixed amount or percentage).
3. The allocation basis must support at least two modes: fixed monetary amount and percentage of the source balance.
4. Users must be able to run the allocation process to generate journal entries that distribute the source account balances to the target accounts according to the defined rules.
5. The system must validate that percentage-based allocation rules sum to 100% across all targets before allowing the rule to be saved.
6. Generated allocation journal entries must reference the allocation rule ID in their Source Document or Description.

## Acceptance Criteria
1. Given a user defines an allocation rule with source account A and two target accounts (60% each -- invalid), when they save the rule, then the system rejects it with "Allocation percentages must total 100%."
2. Given a valid allocation rule (e.g. 60% + 40%), when the user runs the allocation, then two journal entry lines are generated for the target accounts with the correct amounts based on the source balance.
3. Given an allocation rule using fixed amounts, when the allocation is run, then the fixed amounts are used regardless of the current source account balance.
4. Given a user views the allocation rules list, when the screen loads, then all defined rules are listed with their source account, targets, and allocation basis.

## Non-Functional Requirements
| Category      | Requirement                                                              |
|---------------|--------------------------------------------------------------------------|
| Performance   | Allocation run for up to 50 rules must complete within 30 seconds.      |
| Security      | Allocation rule creation and execution require GL accountant role.       |
| Accessibility | WCAG 2.1 Level AA compliance required; all form inputs and data grids must be keyboard-accessible. |
| Usability     | Percentage totals must display a running sum to help users reach 100%.  |
| Other         | Allocation basis options including any ratio codes are pending clarification; see Open Question OQ-029. |

## UI Components Affected
- Account Balance Allocation management screen
- Allocation rule definition form (source, targets, percentages/amounts)
- Allocation run / execute action
- Generated entries list

## BFF Endpoints Needed
- GET /allocation-rules -- list allocation rules
- POST /allocation-rules -- create an allocation rule
- PUT /allocation-rules/{id} -- update an allocation rule
- DELETE /allocation-rules/{id} -- delete an allocation rule
- POST /allocation-rules/{id}/run -- execute an allocation rule and generate journal entries
