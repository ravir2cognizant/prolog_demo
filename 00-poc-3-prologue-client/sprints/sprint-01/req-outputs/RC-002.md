## User Story
As a GL accountant,
I want to add, edit, and delete journal entry lines specifying the account code, currency, debit amount, credit amount, description, and reference number for each line,
So that I can record the complete double-entry accounting transaction with full line-level detail.

## Functional Requirements
1. The journal entry form must display a line-item grid with the following columns: Line Number (auto-assigned), Account (code picker), Account Description (auto-populated from account code), Currency ID (dropdown, defaults to company base currency), Debit (numeric input), Credit (numeric input), Description (text), Reference # (text).
2. The system must auto-populate the Account Description column when the user selects or enters an account code.
3. Each line must accept either a Debit value or a Credit value, but not both simultaneously (or zero in the other field).
4. The user must be able to add new lines to the grid via a dedicated add-row action.
5. The user must be able to delete individual lines from the grid.
6. Line numbers must be automatically assigned sequentially and must re-sequence if a line is deleted.
7. The system must support multi-currency entries: the Currency ID field is per-line and must show valid currency codes.
8. The account picker must allow the user to search for and select accounts from the chart of accounts.
9. A minimum of two lines is required for a valid journal entry (one debit, one credit).

## Acceptance Criteria
1. Given a user clicks Add Line on the journal entry form, when a new row appears in the grid, then the Line Number is auto-assigned sequentially and all other fields are blank and editable.
2. Given a user enters a valid account code in the Account field, when focus leaves the field, then the Account Description field auto-populates with the account name.
3. Given a user enters a value in the Debit field of a line, when they submit the entry, then the Credit field for that line must be 0.00 (and vice versa).
4. Given a user deletes a line, when the deletion is confirmed, then the remaining lines are re-numbered sequentially starting from 1.
5. Given a user opens the account picker, when they type a partial account code or name, then a filtered list of matching accounts is displayed.

## Non-Functional Requirements
| Category      | Requirement                                                                        |
|---------------|------------------------------------------------------------------------------------|
| Performance   | Account description auto-populate must respond within 500ms of account code entry. |
| Security      | Account picker must only show accounts the user's company has access to.           |
| Accessibility | Grid must be navigable by keyboard; each cell must be accessible via tab/arrow keys.|
| Usability     | Numeric input fields must support formatted entry (commas, decimal point).          |
| Other         | Maximum line count per entry is a configurable system limit; see Open Question OQ-006. |

## UI Components Affected
- Journal entry lines grid (editable data grid)
- Account code picker / search dialog
- Currency ID dropdown (per line)
- Numeric input cells (Debit, Credit)
- Add Line / Delete Line action controls
- Line number column (read-only, auto-assigned)

## BFF Endpoints Needed
- GET /accounts?search={term}&companyId={id} -- search chart of accounts for account picker
- GET /currencies -- list valid currency codes
- (Lines are submitted as part of the journal entry: POST /journal-entries, PUT /journal-entries/{id})
