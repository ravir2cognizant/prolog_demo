## User Story
As a GL accountant,
I want to create and manage accrual and prepaid journal entries with their associated reversal schedules,
So that I can accurately record period-end accruals and prepaid expenses that span multiple accounting periods without creating and reversing entries manually each period.

## Functional Requirements
1. The system must provide an Accruals/Prepaid management screen accessible from the General Ledger navigation.
2. The screen must allow creation of recurring accrual or prepaid journal entries with a defined schedule (e.g. monthly reversal, fixed end date).
3. Each accrual/prepaid entry must link to a base journal entry and a reversal rule.
4. The system must generate the recurring journal entries and their reversals automatically according to the schedule.
5. The user must be able to view, edit, and cancel active accrual/prepaid schedules.

## Acceptance Criteria
1. Given a user creates an accrual schedule, when the schedule is saved, then the system generates the required journal entries for each period according to the schedule.
2. Given an active accrual schedule, when a user views it, then they can see all generated and pending entries associated with the schedule.
3. Given a user cancels an active accrual schedule, when cancellation is confirmed, then no further entries are generated for future periods.
4. Given a scheduled period arrives, when the system creates the accrual entry, then a corresponding reversal entry is also created for the next period in Unposted status.

## Non-Functional Requirements
| Category      | Requirement                                                             |
|---------------|-------------------------------------------------------------------------|
| Performance   | Schedule generation must complete within 10 seconds for up to 24 periods.|
| Security      | Accrual/prepaid management requires GL accountant role or higher.       |
| Accessibility | WCAG 2.1 Level AA compliance required; see Open Question OQ-027 for module-specific requirements. |
| Usability     | Schedule definition form must use clear date and period selectors with inline help text. |
| Other         | Accrual schedule generation must be idempotent -- re-running for the same period must not create duplicate entries. |

## UI Components Affected
- Accruals/Prepaid management screen
- Schedule creation form
- Schedule list/grid
- Generated entries list (linked to schedule)

## BFF Endpoints Needed
- GET /accrual-schedules -- list accrual/prepaid schedules
- POST /accrual-schedules -- create a new schedule
- PUT /accrual-schedules/{id} -- update a schedule
- DELETE /accrual-schedules/{id} -- cancel a schedule
- GET /accrual-schedules/{id}/entries -- list generated entries for a schedule
