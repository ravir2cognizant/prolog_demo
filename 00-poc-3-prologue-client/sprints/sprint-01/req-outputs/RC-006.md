## User Story
As a GL accountant,
I want to navigate through journal entries using First, Previous, Next, and Last controls directly from the journal entry form,
So that I can browse and review entries sequentially without returning to a separate search or list screen.

## Functional Requirements
1. The journal entry toolbar must include four navigation actions: First (go to the first entry in the result set), Previous (go to the preceding entry), Next (go to the following entry), Last (go to the last entry in the result set).
2. The system must load and display the selected entry's full header and lines when a navigation action is triggered.
3. The Previous button must be disabled when the currently displayed entry is the first in the set.
4. The Next button must be disabled when the currently displayed entry is the last in the set.
5. If the user has unsaved changes on the current entry when a navigation action is triggered, the system must prompt the user to save or discard changes before navigating.
6. The navigation result set must be based on the user's current filter or context (e.g. all entries for the current company, or the result of a prior search).

## Acceptance Criteria
1. Given a user is viewing journal entry #237, when they click Next, then the form loads the next journal entry and all header and line fields are updated to reflect it.
2. Given a user is on the first journal entry in the set, when the form loads, then the First and Previous buttons are visually disabled.
3. Given a user is on the last journal entry in the set, when the form loads, then the Next and Last buttons are visually disabled.
4. Given a user has unsaved edits on the current entry, when they click Next, then a confirmation dialog asks "You have unsaved changes. Save before navigating?" with Save and Discard options.
5. Given a user clicks Save in the unsaved-changes prompt, when the save completes successfully, then the system navigates to the next entry.

## Non-Functional Requirements
| Category      | Requirement                                                              |
|---------------|--------------------------------------------------------------------------|
| Performance   | Navigation must load the next/previous entry within 2 seconds.           |
| Security      | Navigation must only traverse entries the user has permission to view.   |
| Accessibility | Navigation buttons must have accessible labels (e.g. aria-label="First record").|
| Usability     | Navigation buttons should use standard iconography (|<, <, >, >|).      |
| Other         | Navigation result set definition (filter scope) is pending confirmation; see Open Question OQ-018. |

## UI Components Affected
- Navigation toolbar (First, Previous, Next, Last buttons)
- Unsaved changes confirmation dialog

## BFF Endpoints Needed
- GET /journal-entries?companyId={id}&cursor={id}&direction=next -- cursor-based navigation
- GET /journal-entries/{id} -- load specific entry by ID
- GET /journal-entries/first?companyId={id} -- first entry
- GET /journal-entries/last?companyId={id} -- last entry
