## User Story
As a GL accountant,
I want to import transaction data from external source systems into the general ledger,
So that I can load batches of transactions (e.g. from AP, AR, payroll, or other sub-ledgers) without manual re-entry, reducing errors and processing time.

## Functional Requirements
1. The system must provide a Transaction Import / Download module accessible from the General Ledger navigation.
2. Users must be able to upload a transaction file for import.
3. The system must validate the imported file against a defined format specification before creating journal entries.
4. Valid transactions must be created as journal entries (in Unposted status) in the GL.
5. The system must report any validation errors per transaction row so users can correct and re-import the affected rows.
6. Users must be able to download/export GL transactions in a standard format.

## Acceptance Criteria
1. Given a user uploads a valid transaction import file, when the import is processed, then the system creates journal entries for each transaction row in Unposted status.
2. Given an import file contains rows with validation errors (e.g. invalid account code), when the import is processed, then the valid rows are imported and the error rows are listed with specific error messages.
3. Given an import completes, when the user views the import summary, then they see a count of successfully imported transactions and a count of failed rows.
4. Given a user clicks Download on the transaction download screen, when the export completes, then a file is provided containing GL transactions in the specified format.

## Non-Functional Requirements
| Category      | Requirement                                                              |
|---------------|--------------------------------------------------------------------------|
| Performance   | Import of up to 10,000 transaction rows must complete within 60 seconds. |
| Security      | Transaction import requires GL accountant role.                          |
| Accessibility | WCAG 2.1 Level AA compliance required; file upload and import progress controls must be keyboard-accessible. |
| Usability     | Import progress must be shown during processing.                         |
| Other         | Accepted import file formats are pending confirmation; see Open Question OQ-042. |

## UI Components Affected
- Transaction Import screen
- File upload control
- Import validation error list
- Import summary (success/fail counts)
- Transaction Download screen

## BFF Endpoints Needed
- POST /transactions/import -- upload and process a transaction import file
- GET /transactions/import/{jobId}/status -- poll import job status
- GET /transactions/import/{jobId}/errors -- list validation errors from an import
- GET /transactions/export?companyId={id}&fromDate={date}&toDate={date} -- export transactions
