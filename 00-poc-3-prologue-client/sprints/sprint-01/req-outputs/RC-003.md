## User Story
As a GL accountant,
I want to see a live running total of all debits, all credits, and the difference across all journal entry lines,
So that I can instantly confirm the entry is balanced (Difference = $0.00) before saving or posting it.

## Functional Requirements
1. The journal entry form must display a totals row below the lines grid showing: Total Debit, Total Credit, and Difference (Total Debit minus Total Credit).
2. The totals must update in real time as the user adds, edits, or deletes lines.
3. The Difference value must be prominently highlighted in a contrasting colour (e.g. red) when it is non-zero.
4. The system must prevent posting of a journal entry whose Difference is non-zero (unbalanced entry).
5. The system must prevent saving a journal entry whose Difference is non-zero, displaying an inline validation message.
6. All totals must be displayed with the same currency formatting as the line values (2 decimal places, thousands separator).

## Acceptance Criteria
1. Given a journal entry with lines Debit $1,825.00 and Credit $1,825.00, when the user views the form, then the Totals row shows Total Debit $1,825.00, Total Credit $1,825.00, Difference $0.00.
2. Given a user enters a new debit line of $500.00, when the value is entered, then the Total Debit and Difference update immediately without requiring a save.
3. Given a journal entry with Difference non-zero, when the user attempts to post the entry, then the system blocks the action and displays the message "Journal entry is not balanced. Total debits must equal total credits."
4. Given a journal entry with Difference of $0.00, when the user views the Difference cell, then it is displayed without a warning indicator.
5. Given a journal entry with Difference non-zero, when the user views the Difference cell, then it is displayed with a visual warning (e.g. red text or background).

## Non-Functional Requirements
| Category      | Requirement                                                              |
|---------------|--------------------------------------------------------------------------|
| Performance   | Totals must recalculate within 100ms of any line value change.           |
| Security      | No special requirements beyond the journal entry access control.         |
| Accessibility | Totals row must be labelled for screen readers ("Total Debit", etc.).    |
| Usability     | Difference row must visually distinguish balanced vs unbalanced state.   |
| Other         | Multi-currency totalling behaviour is pending confirmation; see Open Question OQ-009. |

## UI Components Affected
- Journal entry lines grid totals row
- Difference indicator (balance/imbalance visual state)
- Inline validation message for unbalanced save/post attempts

## BFF Endpoints Needed
- None specific to this card -- totals calculated client-side from line data.
- POST /journal-entries and PUT /journal-entries/{id} must enforce balance server-side as well.

## Intra-sprint Dependencies
- Depends on: RC-002 -- totals are computed from the lines grid values.
- Depends on: RC-004 -- posting must be blocked server-side for unbalanced entries.
