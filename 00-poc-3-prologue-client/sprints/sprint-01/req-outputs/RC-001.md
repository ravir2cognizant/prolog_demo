## User Story
As a GL accountant,
I want to create and edit a journal entry header with all required fields (Company ID, Entry Type, Transaction Date, Description, Source Document, Allocation Method, Routing),
So that I can accurately set up a journal entry before adding financial line items.

## Functional Requirements
1. The system must display a Journal Entry form with the following header fields: Company ID (dropdown), Journal Entry Type (dropdown), Journal Entry ID (read-only or auto-assigned), Status (read-only), Transaction Date (date picker), Auto Reversal Date (date picker, optional), Description (text input), Source Document (dropdown), Allocation Method ID (dropdown, optional), Routing (text input, optional), Posted (read-only Yes/No), Posted Date/Time (read-only), Posted User ID (read-only), Edit Date/Time (read-only), Edit User ID (read-only).
2. The system must auto-assign a sequential Journal Entry ID when a new entry is created.
3. The Company ID field must be populated from a list of available companies the user has access to.
4. The Journal Entry Type dropdown must be populated with valid entry types (e.g. Finance Journal).
5. The system must set the Edit Date/Time and Edit User ID fields automatically whenever the entry header or lines are saved.
6. The Status field must display "Unposted" for newly created entries.
7. The system must prevent editing of a posted journal entry's Transaction Date and header fields (except where explicitly permitted).
8. The Source Document field must be populated from a list of valid source document types.

## Acceptance Criteria
1. Given a user opens the Journal Entry form, when they select a Company ID and Journal Entry Type, then both fields show the selected value and the form is ready for further data entry.
2. Given a user creates a new journal entry, when the entry is saved, then the system assigns a unique Journal Entry ID and displays it in the ID field.
3. Given a user saves a journal entry, when the save completes, then the Edit Date/Time field shows the current timestamp and Edit User ID shows the current user's ID.
4. Given a new journal entry, when the form loads, then the Status field shows "Unposted" and the Posted field shows "No".
5. Given a posted journal entry, when a user opens it, then the header fields are read-only and no edits can be submitted.

- Company ID dropdown
- Journal Entry Type dropdown
- Source Document dropdown
- Allocation Method ID dropdown
- Date picker components (Transaction Date, Auto Reversal Date)
- Read-only status/audit fields (Status, Posted, Edit Date/Time, etc.)

## BFF Endpoints Needed
- GET /journal-entries/{id} -- retrieve a single journal entry
- POST /journal-entries -- create a new journal entry
- PUT /journal-entries/{id} -- update journal entry header
- GET /companies -- list companies available to current user
- GET /journal-entry-types -- list valid entry types
- GET /source-documents -- list valid source document types
- GET /allocation-methods -- list valid allocation method IDs
