## User Story
As a GL accountant,
I want to set an auto-reversal date on a journal entry so that the system automatically generates a reversing entry on the specified date,
So that I can create period-end accrual and estimate entries without manually creating the reversal in the following period.

## Functional Requirements
1. The journal entry header must include an optional Auto Reversal Date field (date picker).
2. When an Auto Reversal Date is set and the original entry is posted, the system must automatically create a reversing journal entry with debits and credits swapped, dated on the Auto Reversal Date.
3. The auto-generated reversal entry must reference the original journal entry ID in its Description or Source Document field.
4. The auto-reversal entry must be created in "Unposted" status; it must not be automatically posted.
5. The system must display a visual indicator on the original entry (e.g. a flag or badge) showing that an auto-reversal is scheduled.
6. The user must be able to remove or change the Auto Reversal Date before the original entry is posted.
7. After the original entry is posted, the Auto Reversal Date must become read-only.

## Acceptance Criteria
1. Given a user sets the Auto Reversal Date to a future date before saving, when the entry is saved, then the Auto Reversal Date is stored and displayed in the header.
2. Given a posted journal entry with an Auto Reversal Date, when that date arrives, then the system creates a new Unposted reversing entry with all debit and credit amounts swapped and a reference to the original entry ID.
3. Given a posted journal entry with no Auto Reversal Date, when the entry is viewed, then the Auto Reversal Date field is blank and no reversal is scheduled.
4. Given a user opens a posted entry with an Auto Reversal Date, when they view the Auto Reversal Date field, then it is read-only and cannot be changed.
5. Given an auto-generated reversing entry, when a user opens it, then the description references the originating journal entry ID.

## Non-Functional Requirements
| Category      | Requirement                                                              |
|---------------|--------------------------------------------------------------------------|
| Performance   | Auto-reversal generation must complete within 5 seconds of the scheduled date.|
| Security      | Auto-reversal entries must be attributed to a system service user, not a human user.|
| Accessibility | Auto Reversal Date field must be a labelled date picker.                 |
| Usability     | The scheduled reversal date must be clearly visible in the entry header. |
| Other         | Reversal trigger mechanism (scheduled job vs manual action) is pending confirmation; see Open Question OQ-015. |

## UI Components Affected
- Auto Reversal Date field (date picker in header)
- Auto-reversal scheduled indicator (flag/badge on entry)
- Reversal entry view (linked from original)

## BFF Endpoints Needed
- (Auto Reversal Date is set via PUT /journal-entries/{id} or POST /journal-entries)
- POST /journal-entries/{id}/reverse -- manually trigger reversal or internal scheduled job endpoint
